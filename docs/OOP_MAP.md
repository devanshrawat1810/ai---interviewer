## 2. Core Architectural Pillars

### 1. SOLID Design Principles in Practice
- **Single Responsibility Principle (SRP)**: Each class has one clear responsibility. For example, `InterviewSession` manages the question timeline and responses, while `AIFeedback` solely analyzes performance metrics.
- **Open/Closed Principle (OCP)**: Adding a new question type (e.g. `SystemDesignQuestion`) requires deriving from `Question` and implementing `evaluate()`—zero edits to existing question classes or the interview engine.
- **Liskov Substitution Principle (LSP)**: Any subclass of `Question` (`MCQQuestion`, `TextQuestion`, `CodingQuestion`) or `ILLMClient` can be substituted into consumer routines without altering program correctness.
- **Interface Segregation Principle (ISP)**: Focused, modular repository interfaces (`IUserRepository`, `IQuestionRepository`, `IDailyChallengeRepository`, `IAiUsageRepository`) rather than a single monolithic database interface.
- **Dependency Inversion Principle (DIP)**: `ConsoleUI` and `AdminService` depend only on abstract repositories and `IClock`, never on direct disk I/O or Mongo driver drivers.
